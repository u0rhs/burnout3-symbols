# Retail memory map (from cheat codes and patches)

Addresses in the **NTSC-U retail release (SLUS-21050; PCSX2 CRC `BEBF8793`)** whose meaning is known
from cheat codes and PCSX2 patches. The retail executable has no symbols, so these are the first named
locations in it: the save profile, the player's race state, tuning values, display and HUD layout,
controls, and code locations that the patches change.

**Sources:**

1. **Aero_'s widescreen fix and Ookami & Aero_'s button mapping** from
   [AeroWidescreen/PCSX2-Cheats](https://github.com/AeroWidescreen/PCSX2-Cheats/tree/main/Burnout%203%20Takedown/SLUS-21050)
   (MIT). Both files are included unchanged in
   [`data/burnout3-retail/third-party/AeroWidescreen-PCSX2-Cheats/`](../../data/burnout3-retail/third-party/AeroWidescreen-PCSX2-Cheats).
2. The PCSX2 patch file *Burnout 3 - Takedown (NTSC-U) SLUS-21050.pnach*, generated by
[GameHacking.org](https://gamehacking.org) from its code database, with codes by **Codejunkies**,
**Code Master** and **MadCatz**. A copy is on
[Scribd](https://www.scribd.com/document/876925846/Burnout-3-Takedown-NTSC-U-SLUS-21050-pnach) (uploaded
by lordnuzir). That compilation has no licence, so its codes are not reproduced here: this page and
its tables are rewritten from them. The original file can be generated on GameHacking.org.

Data files:
- [`memory-map.csv`](../../data/burnout3-retail/memory-map.csv): every address, width, meaning, values seen
  and which codes it comes from.
- [`vehicle-ids.csv`](../../data/burnout3-retail/vehicle-ids.csv): the 67 vehicles' IDs.
- [`event-medals.csv`](../../data/burnout3-retail/event-medals.csv): the medal byte of each World Tour event.

**Reliability:** the codes are community work collected over years. Some disagree with each other
(two events on one address, two numbers on one headline), a few were stored still encrypted and can't be
read, and some titles are misspelled. Conflicts are marked in the CSVs.

## Reading the codes

The `.pnach` lines are `patch=1,EE,<code>,extended,<value>`, in Code Breaker / raw format: the first hex
digit of the code is the operation, the rest the address.

| First digit | Operation |
|---|---|
| `0` / `1` / `2` | Write 8 / 16 / 32 bits |
| `3` | Increment or decrement (next line gives the address) |
| `4` | Serial write: `4aaaaaaa nnnnssss`, then the value: `n` writes `s` words apart |
| `D` | If the 16-bit value at the address equals the low half of the value, run the next line |
| `9`, `F` | Hooks / "master codes" that let the cheat device run |
| `8`, other `9…`/`2…` outside RAM | Encrypted Code Breaker lines left undecrypted (unusable) |

## Save profile (`0x0051BB3C`–`0x0051CA9B`)

The player's progress, as the game keeps it in memory (and presumably saves it to the memory card;
compare the [progression and saves](../systems/progression-saves.md) classes, `CB3Profile`,
`CB3ProgressionManager`).

| Address | Width | Holds |
|---|---|---|
| `0x0051BB3C` | 32 | Cash (as titled by the code) |
| `0x0051BB40` | 32 | Burnout points |
| `0x0051BB44` | 32 | Total crash damage |
| `0x0051BC60` | 32 | Total takedowns |
| `0x0051BE44`–`0x0051BE7C` | 32 each | Trophy counters: first car / big rig / Psyche Out / Revenge / double / triple takedown, takedown rampage; bus, tram, trailer and wall takedowns in a race; aftertouch takedowns; takedowns in a race and in a Road Rage event (see the CSV for each address) |
| `0x0051BE84` | 8 | A medal byte set by an "all gold medals" code |
| `0x0051BE86`–`0x0051BF32` | 8 × 173 | **Medal of each World Tour event**, one byte each; 3 = gold ([event list](../../data/burnout3-retail/event-medals.csv)) |
| `0x0051BF33`–`0x0051BF46` | 8 × 20 | Signature takedowns 1–20 (1 = have) |
| `0x0051BF47`–`0x0051BF50` | 8 × 10 | Crash headlines 1–10 (1 = have) |
| `0x0051BF52`–`0x0051BF93` | 8 × 66 | Cars in the garage (1 = have) |
| `0x0051C124` | 32 | World Tour takedowns |
| `0x0051C9F0`–`0x0051CA9B` | 8 × 172 | Event unlocked flags (1 = unlocked) |

The event medal bytes run in the game's own event order, region by region; 139 of the 173 are named
by the codes. The hard-coded event lists in the code (`CB3HardCodedRaceStageList`,
`CB3HardCodedCrashStageList`, `CB3HardCodedSpecialEventList`) are the likely source of that order.

## Race and player state

| Address | Width | Holds |
|---|---|---|
| `0x0064E484` | 32 | Current lap, from 0 |
| `0x0064E4BC` | 32 | Score |
| `0x0064E56C` | 32 | Boost bar count / level (3 = full length) |
| `0x0064E570` | float | Boost maximum (720.0 with three bars of 240) |
| `0x0064E574` | float | Boost amount |
| `0x0064E584` | float | A boost multiplier (2.0 with max boost) |
| `0x0064ED10` / `0x0064ED14` | 32 + 32 | **Selected vehicle ID**: low and high word ([vehicle table](../../data/burnout3-retail/vehicle-ids.csv)) |
| `0x00665FC0` | float | Chase camera distance multiplier (1.0 normal) |

**Vehicle IDs.** The high word is the same for every car of a class, and the low words of one model
line differ by fixed steps across classes (all *Tuned* cars end in `…607000`, all *Prototypes* in
`…FCB000`). The pair is probably one 64-bit ID, matching Criterion's `CGtID` class (`GtID.cpp`), with
the class in the high word:

| High word | Class |
|---|---|
| `0x5B55839B` | Compact |
| `0x5C3791C1` | Coupe |
| `0x961647D1` | Muscle |
| `0xB8A15FE9` | Sport |
| `0xB959BADE` | Super |
| `0x790798FB` | Special |
| `0x77042838` | Heavyweight |

## Tuning and physics values

| Address | Type | Holds | Normal / values seen |
|---|---|---|---|
| `0x0052267C` | float | **Simulation time step per frame** | `1/60` (0.016667) normally; 1/120, 1/30, 1/15 and others for slow and fast game speed |
| `0x0057CEC4` | float | Boost gain rate | 512.0 and 1000.0 in codes |
| `0x0057CF84` | float | A boost value | 8.0 in a code |
| `0x0057C5AC` | float | Nitrous boost speed | 500.0, 1000.0 |
| `0x004E068C` | float | Crash bounce / launch factor | 1.75, 2.0, 100.0 |
| `0x004E06A4` | float | Crash explosion strength | −8.0 |
| `0x004E06AC` | float | Crash-mode gravity | 32.0 |
| `0x004E1634` | 32 | Threshold for wrecking against other vehicles | `0x7FFFFFFF` (almost immune), `0` (easy wrecks) |
| `0x004F50DC` | 16 | **Pad 1 buttons**, active-low | e.g. `0xFDEF` = R2+Up held |

The time step is the value the [race clock](../systems/game-flow.md) advances the simulation by, one
step per frame at 60 Hz. The `0x004E06xx`–`0x004E16xx` floats sit together and are probably one tuning
block of the crash code ([crashes and scoring](../systems/crash-scoring.md)); the boost values belong
with `CB3Burn` ("Burn" is Criterion's name for boost).

## Display and HUD layout (widescreen patch)

Burnout 3 already has a widescreen option, a flag byte at **`0x00665ECD`**. It changes the projection
but not the 2D layout, which is built for a 640-wide screen. The widescreen patch turns the flag on and
adjusts every 2D element, which locates them all:

| What | Where | 16:9 value used |
|---|---|---|
| Widescreen flag | `0x00665ECD` (byte) | 1 |
| Field of view / aspect ratio, single player | `0x004E0A38` / `0x004E0C70` (floats) | 1.33333 / 1.77778 |
| Field of view / aspect ratio, split screen | `0x004E0C7C` / `0x004E0C80` | 1.77778 / 3.55556 |
| HUD width scale | `0x004E105C` | 0.00117188 |
| HUD X position, player 1 / 2 | `0x006682B0` / `0x00669B30` | +80 |
| HUD corner X positions | `0x004B7658`, `…68`, `…78`, `…88` | ±0.1975 |
| HUD render width and X, player 1 / 2 (code) | `0x001A176C`, `0x001A1774` / `0x001A17D0`, `0x001A17D8` | 854, −107.5 |
| "Get Ready! GO" width and X (code) | `0x00134F2C`, `0x00134F74` | 854, 0.375 |
| Crash camera border | `0x004CA638`–`0x004CA660` | widths 853.3, X −107.5 |
| Crash camera list backing and text (code) | `0x003D70BC`, `0x003D7238`, `0x003D72F4` | 854, −107.5 |
| Menu width and X (code) | `0x0030D7E4`, `0x0030D834` | 480, +80 |
| Menu top / bottom borders (code) | `0x0031B180`, `0x0031B1F4` / `0x0038AE00`–`0x0038AE4C` | 854 |
| Menu checkerboard (code) | `0x0031D6E4`–`0x0031D854` (five widths, five X positions) | 854 |
| Loading background (code) | `0x0031DA20`, `0x0031DA40` | 854 |
| Replay top / bottom bars (code) | `0x003A6984`, `0x003A6998` / `0x003A69C8`, `0x003A69DC` | 854 |
| Car select overlay | `0x004D1568` / `0x004D1570` | X −107.5, width 853.3 |
| Frontend globe field of view / aspect (code / float) | `0x00211E8C` / `0x004E0C3C` | 1.33333 / 1.77778 |
| Globe glow size / aspect | `0x003B17F4` (code) / `0x004E0A94` | 375.0 / 1.44444 |

"(code)" means the value is an immediate inside an instruction: the patch rewrites the instruction, or
jumps to its own code. That code sits in **`0x004858C0`–`0x004859E7`, unused space in the retail image**.
These spots are in the 2D renderer and the [HUD](../systems/hud.md), [frontend](../systems/frontend.md) and
[2D toolkit](../systems/ui-2d.md) classes (`CB3HUDManager`, `Gt2dRendererPS2`, `CB3Globe2dObject` …).

## Controls (button mapping patch)

The gameplay controls are set by immediates in one stretch of code at `0x0012F218`–`0x0012FAD0`, most
likely the default mapping in `CB3ControllerMappingPS2` ([core and input](../systems/core-platform.md)).
Each value is a button number:

| Action | Address | Default |
|---|---|---|
| Accelerate | `0x0012FAAC` | Cross |
| Accelerate (analog) | `0x0012FAD0` | right stick up |
| Brake | `0x0012F9DC` | Square |
| Brake (analog) | `0x0012FA00` | right stick down |
| Look back | `0x0012F308` | L1 |
| Boost & Impact Time | `0x0012F218` | R1 |
| Next music track | `0x0012F4C8` | L2 |
| Change view | `0x0012F410` | Triangle |
| Crash Breaker | `0x0012F690` | R2 |

Button numbers: 0 Triangle, 1 Square, 2 Cross, 3 Circle, 4–7 D-pad up/down/left/right, 8 Start,
9 Select, 0x0A L1, 0x0B L2, 0x0C R1, 0x0D R2, 0x0E L3, 0x0F R3, 0x10–0x13 left stick up/down/left/right,
0x14–0x17 right stick up/down/left/right, 0xFF none.

## Code locations

Places the codes patch in the executable. They are anchor points for naming retail functions: each one
sits in a function whose behaviour the code describes.

| Address | Patched to | Effect | Probably in |
|---|---|---|---|
| `0x00134B08`, `0x00134C44` | `nop` | Shows the world time on screen | A debug display left in the HUD or game code |
| `0x0014E07C` | `li v1,3` | Crashing fills the boost meter ×4 | Boost (`CB3Burn`) handling of a crash |
| `0x0014E084` | `nop` | Extra max boost isn't lost when crashing | the same |
| `0x0015BB80` | `li v0,0` | Crash Breaker always available | Crash mode logic (`CB3OfflineSingleCrashLogic` or `CB3CrashScore`) |
| `0x0015BB88` | `nop` | Crash Breaker right after wrecking | the same |
| `0x001A4940` | `j 0x000C2020` | Hook for a max-boost routine | Boost update |
| `0x001B7220` | `jr ra; nop` | Vehicles pass through each other | **Start of a vehicle–vehicle collision function** |
| `0x001B7378` | `nop` | the same, another way | the same function |
| `0x001D3D2C` | `nop` (original `sw v1,-0x5F34($gp)`) | Stops the race timer | Race timer update; the timer is a `$gp`-relative global |
| `0x0027CF26` | upper half `0x1000` | "Infinite time to play" | A time-limit check |
| `0x002147A8` | `jal` to a code cave | Hook used by the MadCatz master code | |
| `0x0030B284` | `j 0x000C2000` | Hook for an infinite-boost routine | Boost update |
| `0x000C2000`–`0x000C2030` | — | Free low memory the MadCatz codes put their routines in | |
| `0x00129B50`, `0x0034BEE4` | — | Code Breaker hook points ("enable codes") | |

Matching these functions to the prototype names (see [decompilation](../avenues/decompilation.md))
would turn each into a named, documented retail function.
