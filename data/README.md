# Data

The exported data, as text. Everything except `originals/` is generated by
[`tools/rebuild.sh`](../tools/rebuild.sh) from the original disc folders, which are not part of the
repository.

No game code, executables, modules or assets are included, and no byte dumps: only symbols, maps, debug
information rewritten as declarations, strings, file listings, executable headers and decoded tables.
The `originals/` folders keep the two text link maps from the discs, for reference.

| Folder | From |
|---|---|
| [`burnout3-prototype/`](burnout3-prototype/README.md) | The Burnout 3 prototype (link maps of four builds, assert files, modules, disc) |
| [`burnout3-retail/`](burnout3-retail/README.md) | The Burnout 3 NTSC-U retail disc, SLUS-21050 (disc listing, strings, value database, memory map from cheat codes and patches) |
| [`burnout3-review-us-2004-07-20/`](burnout3-review-us-2004-07-20/README.md) | The US review build of 20 July 2004 (disc listing, strings, headers, value database; no symbols) |
| [`burnout3-review-pal-2004-07-20/`](burnout3-review-pal-2004-07-20/README.md) | The PAL review build of 20 July 2004 (the same) |
| [`burnout2-prototype/`](burnout2-prototype/README.md) | The Burnout 2 prototype of 29 July 2002 (symbols and DWARF 1 debug info) |
| [`burnout-revenge-prototype/`](burnout-revenge-prototype/README.md) | The Burnout Revenge PS2 prototype of 14 July 2005 (symbols and GCC debug info) |
| `*/originals/` | The original text link maps (see below) |
| [`hashes.tsv`](hashes.tsv) | Size, CRC32, MD5 and SHA-1 of every source file ([as a table](../docs/reference/hashes.md)) |

Every file with its size and a direct link: [symbols and maps](../docs/files.md). The documentation built on
this data starts at the [Home](../README.md) page.

## */originals/

| Folder | Files |
|---|---|
| [`burnout3-prototype/originals/`](burnout3-prototype/originals/README.md) | `DNAT_200.MAP`, the text link map of the prototype executable |
| [`burnout2-prototype/originals/`](burnout2-prototype/originals/README.md) | `IOP/B2STRE~1.XMA`, `IOP/GTFSDV~1.XMA`, `IOP/GTFSHO~1.XMA`: text link maps of three IOP modules |

The binary maps (`B3DEBUG.MAP`, `B3INTERN.MAP`, `B3O0PCH.MAP`) and the assert files (`.AST`) are kept only
as their full text exports in `maps/`. Executables, IOP modules and other disc files are not kept.

## burnout3-prototype/maps/

From the four link maps and two assert files of the prototype disc
([formats](../docs/formats/codewarrior-maps.md)).

| Map | Build | Executable on the disc? |
|---|---|---|
| `DNAT_200.MAP` (text) | the one on the disc, linked 3 June 2004 | yes, but six days newer: game-code addresses drift by up to −0xCE40 (libraries match exactly) |
| `B3DEBUG.MAP` (binary) | debug, 9 June | no |
| `B3INTERN.MAP` (binary) | internal, 2 June | no |
| `B3O0PCH.MAP` (binary) | unoptimised `-O0`, 9 June | no |

| File | Contents |
|---|---|
| `<map>.symbols.txt` / `.csv` | Every symbol: address, size, section, name, library and object file. The txt is grouped by object file in link order |
| `<map>.source_files.txt` | Every object file with code: first address, function count, code size |
| `classes.txt` | 890 classes and every method in any of the four maps, with its address in each build |
| `vu_microcode.txt` | The VU programs and their labels |
| `DNAT_200.unreferenced.txt` | Symbols the linker dropped: code that existed in the source but is not in the executable |
| `DNAT_200.linker_symbols.txt` | Values defined by the linker script: section bounds, `_gp`, stack, BSS |
| `DNAT_200.MAP.txt` | The original text map (line endings fixed), including the reference tree |
| `B3DEBUG.AST.txt`, `B3INTERN.AST.txt` | The assert expressions of the debug builds, with offsets |

**Binary-map caveat:** the tool that wrote the three binary maps cut each line at its first `)`.
Names containing `)` lost their object file, and `const` methods lost the ` const`. The object is
recovered by looking the name up in the other maps; where none has it, it reads `(object unknown)`.

The `-O0` map has about 2,700 more functions than the others: small header functions that the
optimised builds inlined.

## burnout3-prototype/modules/, burnout2-prototype/modules/

IOP modules and secondary ELFs that kept symbols, each exported like an executable (below): symbol
tables and, where present, debug information as text. The modules themselves are not included.
`B3ROUTE.IRX`, `RWSCOMMS.IRX` and Burnout 2's `B2*`/`GTFS*` modules also have debug info. Duplicate
copies are exported once. Overview: [IOP modules](../docs/reference/iop-modules.md).

## burnout2-prototype/SLUS_204.97/

The Burnout 2 executable kept its symbol table and its **DWARF 1** debug information
([format](../docs/formats/codewarrior-dwarf1.md)).

| File | Contents |
|---|---|
| `symbols.txt` / `.csv` | All 12,023 symbols, C++ names demangled |
| `types.h` | 969 classes, structs, unions and enums: every field with its offset, sizes, base classes, enum values, and each class's functions. 79 names have more than one layout (`VARIANT`) |
| `functions.txt` / `.csv` | 2,309 functions with debug info: address range, signature with parameter names, source file, line range |
| `globals.txt` | 1,828 global and file-static variables with type and address, vtables included |
| `source_outline/` | One file per source file (288), mirroring Criterion's `gamesource\` tree: each function's signature, parameters and locals (with the register or stack slot each used), scopes and lines. `renderware_and_libraries/` holds files compiled without a path |
| `line_numbers.csv` | 76,449 address → source line pairs |

CodeWarrior did not record `const`, typedefs or member-function declarations; `bool` appears as
`int` or `unsigned char`; `u_long128` is the EE's 128-bit integer.

## burnout-revenge-prototype/SLUS_212.42/

The Burnout Revenge July 14, 2005 PS2 executable kept its symbol table and its **GCC stabs** debug information
([format](../docs/formats/gcc-stabs-mdebug.md)). Revenge was built on Burnout 3's code (`CB3X` became `CB4X`);
the [Revenge lineage pages](../docs/reference/revenge-class-lineage.md) connect the two. Written by
`tools/export_revenge.py`; neither the executable nor its link map (`B4EXTERN.MAP`, used for demangled names)
is copied.

| File | Contents |
|---|---|
| `symbols.csv` | All 21,798 named symbols (12,023 functions), demangled where the link map has the name |
| `types.h` | 2,789 layouts of 2,717 classes, structs, unions and enums: every member with its offset, base classes, enum values, and each class's **methods** (return type, parameters, virtual/static/const). 62 names have more than one layout (`VARIANT`) |
| `functions.txt` / `.csv` | 9,416 linked functions with debug info: address range, signature with parameter names, source file (`demangled`: the types-only name) |
| `unlinked_functions.csv` | 3,402 functions the debug info describes but the linker dropped |
| `globals.txt` | 4,220 global and file-static variables with type, and address and size where the symbol table has them |
| `source_files.txt` | The 861 source files with code, at Criterion's paths (`GameSource/Hud/…`, `GameShared/GameClasses/Graphical/2d/…`), with function counts and code sizes |

Unlike Burnout 2's CodeWarrior debug info, GCC records `const`, typedef names and member functions. It drops
`const` on pointer parameters, so signatures take parameter types from the mangled names. No line numbers yet.

## burnout3-retail/: memory map and third-party patches

| File | Contents |
|---|---|
| `function-names.csv` | 1,146 retail function names carried from Nahelam's PAL list (`tools/map_pal_names.py`), with a verification column ([page](../docs/reference/retail-function-names.md)) |
| `nahelam-mods.csv` | Every US address Nahelam's mods change, with the mod and the nearest named function ([page](../docs/reference/nahelam-mods.md)) |
| `memory-map.csv` | Retail addresses with width, meaning, values seen and source ([page](../docs/reference/retail-memory-map.md)) |
| `vehicle-ids.csv` | The 67 vehicles' IDs (the two words at `0x0064ED10`/`0x0064ED14`) |
| `event-medals.csv` | The medal byte of each World Tour event in the save profile |
| `third-party/AeroWidescreen-PCSX2-Cheats/` | Aero_'s widescreen patch and Ookami & Aero_'s button mapping patch, unchanged, with their MIT licence |

These are written by hand from the sources named on the page, not by `tools/rebuild.sh`.

## */disc/

For each of the three discs ([overview](../docs/discs.md)):

| File | Contents |
|---|---|
| `files.txt` / `.csv` | Every file: path, size, date, detected format |
| `<exe>.headers.txt` | The main executable's ELF header, program headers and section headers |
| `strings/<exe>.strings.txt` | Printable strings of the main executable with their load addresses |
| `strings/<exe>.strings.<kind>.txt` | The same, sorted into file paths, format strings, identifiers, expressions and other text |
| `vdb/` | The value database decoded: section 1 as (key hash, value) pairs; the undecoded rest is not included ([value database](../docs/reference/value-database.md)) |
